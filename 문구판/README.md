# 문구판 웹앱 (Apps Script)

주요 선도채널 콘텐츠 DB 시트에 붙은 Apps Script 웹앱. 검증된 기성 문구를 빨리 찾고, '내 판정' 탭에 판정을 적는 화면이다.

| 파일 | 역할 |
|---|---|
| `AppUI.html` | 화면. Apps Script 프로젝트의 `AppUI` HTML 파일 |
| `AppAPI.gs` | 서버(스냅샷·저장). v3에서 바뀐 것 없음 |
| `AP_backfill.gs` | v3 도입 때 한 번만 쓰는 옛 판정 태그 소급. 실행 뒤 지워도 된다 |
| `태그_소급_목록.md` | 소급 태그 124건과 애매해서 뺀 20건. PD 확인용 |

## v3 (09-29) — 바로 쓰기 어려운 이유 태그 + 걸러낸 문구 숨기기

- 판정 상자 위에 태그 5개(여러 개 선택): **과장 · 허위 · 국뽕 · 교양형 · 채널 밖 주제**. 태그만 골라도 저장된다.
- 저장하면 새 열 없이 J열 첫 줄에 `[바로 쓰기 어려움] 과장 · 국뽕`, 그 아래 줄에 서술이 적힌다. 시트 구조와 `AppAPI.gs`·`Pipeline.gs`는 그대로다.
- 상단 스위치 **걸러낸 문구 숨기기**를 켜면 태그가 달린 문구를 문구판·문구 찾기의 모든 목록에서 뺀다. 판정 필요 카드와 서술만 있는 판정은 그대로 보인다. 스위치 상태는 브라우저에 기억된다.
- 걸러내는 기준은 PD가 단 태그뿐이다. L열(부읽남 적합)이나 서술 속 단어로 추측해 거르지 않는다. "과장이 있지만 쓸 수는 있다" 같은 서술이 많아서다.
- 태그 목록은 `AppUI.html`의 `CUT_TAGS` 한 곳에서 고친다. 이미 적힌 옛 태그 이름도 그대로 읽힌다.

## 적용 순서 (Apps Script 편집기, u/1 계정)

같은 파일을 Drive '문구판' 폴더에도 올려 두었다(09-29, 저장소 파일과 바이트 단위로 같음):
`AppUI_v3.html` (id `11JVtn2kNOKwGcQtuXTGvixlJDmJspHdV`), `AP_backfill.gs` (id `1sdsqe-9iiQ9fBoHbd7RZvTMX5dKg1DRz`).

1. `AppUI` HTML 파일 내용을 이 저장소의 `AppUI.html`로 통째로 바꾼다.
2. 새 스크립트 파일 `AP_backfill`을 만들고 `AP_backfill.gs`를 붙인다.
3. `AP_backfillPreview`를 실행해 로그를 본다. "붙일 예정 124행"이 나오면 된다(그사이 서술을 고친 행은 건너뜀으로 나온다).
4. `AP_backfillApply`를 실행한다. 다시 실행해도 이미 태그가 있는 행은 건너뛴다.
5. 배포 → 배포 관리 → 기존 웹앱 배포 수정 → 새 버전. 웹앱 주소는 그대로다.
6. (선택) `AP_backfill` 파일을 지운다.

## 확인한 것 (09-29, 실데이터)

09-29 20:38 스냅샷(카드 1,191장)과 '내 판정' 284행으로 만든 시험 페이지에서, `google.script.run`을 흉내 내 헤드리스 Chromium으로 35개 항목을 확인했다.

- 스위치를 켜면 태그 달린 89장이 빠지고, 레퍼런스가 808장에서 719장이 된다. 판정 필요와 쇼츠는 그대로다. 대분류 필터와 문구 찾기에서도 같은 기준으로 빠진다.
- 태그만 저장, 태그+서술 저장, 서술만 저장, 빈 저장 거부, 고치기(기존 태그가 눌린 채 열림, 안 바꾸면 저장 안 함, 태그를 모두 끄면 서술만 남음)를 확인했다.
- 스위치가 켜진 채 태그를 달면 카드가 목록에서 빠지고 개수가 줄어든다.
- 390px 폭에서 가로 스크롤이 없고, 페이지 오류가 없다.
